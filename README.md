# tg2joomla

کانال تلگرام → مطلب جوملا ۶. هر پیام «طبق ساختار» کانال، بلافاصله (با حداکثر ~۵ دقیقه تأخیر) به‌صورت مطلب منتشرشده در سایت درج می‌شود — بدون بازنویسی متن.

## ساختار پیام
- **سطر اول = عنوان مطلب**، سطرهای بعدی = متن مطلب. (متن عیناً درج می‌شود؛ هیچ تغییری نمی‌کند)
- پیام متنی → دسته خبر
- عکس + کپشن (ساختار بالا) → عکس روی سایت آپلود و ابتدای مطلب قرار می‌گیرد، دسته خبر
- فایل Audio پیوست‌شده (mp3 و ...) → روی سایت آپلود و با پخش‌کننده در **دسته صوتی** منتشر می‌شود (کپشن اگر طبق ساختار باشد، تیتر و متن مطلب می‌شود)
- هر پیام دیگر (ویدئو، فایل غیرصوتی، تک‌خطی، نظر) → نادیده گرفته می‌شود
- ویرایش پیام‌ها منتشر نمی‌شود

## تنظیمات یک‌باره در جوملا
1. **System → Plugins**: پلاگین‌های *Web Services - Content* و *Web Services - Media* را فعال کن.
2. **Users → Your Profile → تب API Tokens**: توکن API بساز (کاربر باید Super User باشد).
3. شناسهٔ دستهٔ خبر و دستهٔ صوتی را از **Content → Categories** (ستون ID) بردار.
4. اگر آپلود mp3 خطای «نوع فایل مجاز نیست» داد: **System → Media → Allowed Audio Extensions** بررسی شود.

## تنظیمات تلگرام
- بات باید **ادمین کانال** با مجوز ارسال پیام باشد.
- بات نباید webhook فعال داشته باشد (خطای 409 در لاگ یعنی webhook خارجی روی بات است).

## GitHub Secrets (Settings → Secrets and variables → Actions)
| نام | مقدار |
|---|---|
| `BOT_TOKEN` | توکن بات تلگرام |
| `JOOMLA_BASE` | `https://koohnameh.ir` |
| `JOOMLA_TOKEN` | توکن API جوملا |
| `NEWS_CATEGORY_ID` | شناسه دسته خبر |
| `AUDIO_CATEGORY_ID` | شناسه دسته صوتی |

## اجرا
هر ۵ دقیقه خودکار (Actions). اجرای دستی: تب Actions → sync → Run workflow.
اجرای اول تاریخچه انبوه کانال را منتشر نمی‌کند؛ از اولین پیام‌های تازه، انتشار شروع می‌شود.

فایل `state/processed.json` جلوی انتشار تکراری را می‌گیرد و با هر اجرا commit می‌شود.
خطاهای دائمی (۴xx) در `debug.log` ثبت می‌شوند؛ خطاهای موقت (شبکه/۵xx) بی‌صدا در اجرای بعدی دوباره تلاش می‌شوند.
